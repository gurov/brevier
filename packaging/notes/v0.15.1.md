Fixes, most of them found by fuzzing, Wikipedia without "[edit]", and a TLS update. Updating is recommended on every platform.

**A page that trips Brevier no longer closes it.** If laying out a page failed inside Brevier, the window closed with every tab, and on the phone the app closed. Now that tab shows a short page instead: Brevier tripped over this page, your browser can still show it, and where to report the address. The other tabs stay as they were.

**Found by fuzzing.** Brevier's core now runs under cargo-fuzz, which feeds it mutated pages, feeds, Markdown and notes, and checks more than that it does not crash. The first passes found these, all fixed:

- A word with a letter whose lowercase takes a different number of bytes, such as "İçişleri" in an English article, could crash the layout. Such a word is now set without hyphenation.
- A page with broken JSON-LD, the metadata block many sites carry, could crash Brevier through a bug in a library it reads that block with. Only JSON-LD that parses as valid JSON reaches it now.
- The object replacement character (U+FFFC) in a page's own text confused the page model, which uses that character to mark images and tables. The text now drops it.
- A note left inside a run of identical characters, such as "=====", could move to the neighbouring place. It now stays where it was left.

**Wikipedia without "[edit]".** On Wikipedia and other wikis built on MediaWiki, the "[edit]" link beside each heading stood as a line of its own under it. It is gone; a link to an article not yet written stays, since it is part of the text. A few headings that were dropped or stood in the wrong place, such as "See also" and "References", are now where they belong.

**TLS.** rustls 0.23.46, rustls-webpki 0.103.16 and webpki-root-certs 1.0.10 fix RUSTSEC-2026-0346 to 0349, 0382 and 0383; among them, an unauthenticated reply from a server could downgrade later connections to classical key exchange.
