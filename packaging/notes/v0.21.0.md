A page that brings Brevier down no longer does it again on every start, big pictures take much less memory, and on Windows the window starts faster and opens once however many times you click. The first two came from a reader's letter, the Windows start from a report here (#61) and from trying it on a busy laptop.

**A page that brought Brevier down waits (#57).** The tabs come back on start and the front one loads at once, so a page that crashed the app crashed it again on every start, and the way out was clearing the app's storage — the history, bookmarks, notes and archive with it. Such a crash can't be caught from inside: the system kills an app that runs out of memory. So now, while Brevier opens a page, lays it out or decodes its pictures, a small file in the data folder, `working.txt`, names the page, and it goes away when the work is done. If Brevier closed with the file still there, the next start does not load that page by itself: the tab says **Brevier closed while opening this page**, with **Open it again** and **Open in your browser**. In the window and on the phone. If it closes again, turn off **Images** in Settings and try once more — and an issue with the address helps fix it.

**Big pictures take less memory (#58).** The phone decodes up to four pictures at once, and an article with a gallery of full-size photos could need more memory than Android gives an app. Pictures over 4 megapixels now take turns, and a big one is first reduced by averaging to twice the column's width, then scaled down the careful way: four 6000×4000 photos at once used to peak at 585 MB and now at 196 MB, and they look the same. This is the likeliest cause of the crash in #58, but it is not confirmed yet.

**Windows.**

- **A faster start.** GTK's text engine rebuilt its list of every font on the system twice for each of Brevier's seven font files; on a laptop with many fonts that was 2.4 seconds of every start. The installer now installs Noto Sans and Noto Sans Mono for you alone — as "Noto Sans (Brevier)" and so on, so a Noto Sans you installed yourself stays as it is, and uninstalling removes them — and the window, finding them installed, registers nothing. Run from the zip, it registers them as one collection, once instead of seven times.
- **One window.** A second click on the icon while the window was still coming up started another copy; now it brings up the window that is starting. The same on Linux, where the start is quick enough that it rarely showed.
- **If the window does not open at all (#61).** On some older laptops GTK crashes when the graphics driver does not name its OpenGL renderer. Until that is fixed, set the user environment variable `GSK_RENDERER` to `cairo` (Start → "Edit environment variables for your account" → New), and the window opens without OpenGL.
