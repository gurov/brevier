Brevier comes to Android, and pages you have read open from your own copy.

**Android.** A native front-end over the same core: the article is set in the same type, drawn in native text rather than a WebView, with tabs, the shelf (contents, the project's documentation, the site's navigation), find on page, zoom, saving, history, bookmarks, settings and a session that comes back. Brevier can be the default browser and still hands a page on to another one. Download `brevier-0.2.0-arm64.apk` below and open it; Android asks once to allow installs from the app you opened it with. The APK is signed with the release key whose SHA-256 fingerprint is
`30:A4:32:B8:2F:3E:F0:FC:E5:F4:68:1F:D7:F9:FE:20:5F:4B:17:A2:F4:34:19:C2:45:0C:A2:6B:E6:8D:34:80`.

**A week of reading on disk.** An article opened again within a week comes from a copy on disk, images included — no fetch, no extraction — and the status line says how old the copy is. Reload (`Ctrl+R`, `F5`, or the menu) fetches the page as it is now. A list of links is always fetched fresh; "Forget everything" deletes the copies with the history.

**The check, finished.** `brevier:check/<url>` — or **Check this page** in the menu — opens the report inside Brevier. `brevier --check` takes several addresses and draws an SVG badge with `--badge`, and the repository is now a GitHub Action that fails a build below a pass mark. New findings: long redirect chains, headings set as images, tables built from `div`s, captions outside `<figcaption>`, a missing date.

Also: the history and bookmarks pages no longer link to each other; the "Forget everything" dialog lost a run of stray spaces.

Files: `brevier.flatpak` (any distribution, with Flatpak), `brevier-0.2.0-x86_64-linux.tar.gz` (GTK 4 from the system), `brevier-0.2.0-arm64.apk` (Android 7 and later, 64-bit ARM), and `SHA256SUMS`.
